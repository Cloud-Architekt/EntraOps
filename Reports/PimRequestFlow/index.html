PIM Request Flow

Visualize Entra ID Privileged Identity Management (PIM) role settings from a captured Tenant Governance Snapshot as a filterable Sankey flow - Role → Assignment path → Requirement → Approval → Notification - the same pattern as Conditional Access Analysis's CA Policy Flow and Access Package Flow. Every role is expanded into up to three assignment paths - activating an eligible assignment (self-service PIM request), and an administrator directly assigning an eligible or active assignment - each clustered by the input requirements, approval workflow and notification settings governing it. Roles are enriched with their access tier (from the optional EAM Dashboard classification) to help identify privileged roles that can be activated or assigned without MFA or approval.

No Configuration Analyzer dataset found. This app reuses the same dataset as Configuration Analyzer - generate ../ConfigurationAnalyzer/data/configuration-analyzer-data.js from your repository's git history first:

Import-Module ./EntraOps -Force; New-EntraOpsTenantGovernanceConfigurationAnalyzerData

The Tenant Governance Snapshot feature must be enabled (EntraOpsConfig.json › TenantGovernanceSnapshot.EnableTenantGovernanceSnapshot) and at least one snapshot must have captured the microsoft.entra.roleSetting (and, for role descriptions, microsoft.entra.roleDefinition) resource types with Save-EntraOpsTenantGovernanceSnapshotJson. Then reload this page.

Optionally generate ../EamDashboard/data/eam-dashboard-data.js (New-EntraOpsPrivilegedEamDashboardData) too, so every role can be enriched with its Enterprise Access Model tier - without it, every role shows as Unclassified and tier-dependent filters/flags are unavailable.

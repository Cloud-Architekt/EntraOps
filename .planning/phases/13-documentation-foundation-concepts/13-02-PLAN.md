```markdown
# Concepts

EntraOps implements Microsoft's Enterprise Access Model (EAM) — [see the full framework](https://aka.ms/SPA).

## Why Tiers Exist

[Explain: privilege separation is the core principle of EAM. Highly privileged accounts (ControlPlane) are separated from operational accounts (ManagementPlane) and end-user accounts (UserAccess) to limit blast radius of credential compromise. EntraOps surfaces this classification for the reader's tenant so they can see who holds which level of access.]

## The Three Tiers

### ControlPlane

[Define: Identities with unrestricted or near-unrestricted access to the tenant — global admins, privileged role assignments, and equivalent. Highest privilege in the hierarchy.]

**In the GUI:** ControlPlane identities appear in the ControlPlane KPI card on the Dashboard. Click the card to open Object Browser filtered to ControlPlane objects.

### ManagementPlane

[Define: Identities with significant operational access — workload admins, service principals with broad permissions — but scoped below global admin. Mid-level privilege.]

**In the GUI:** ManagementPlane identities appear in the ManagementPlane KPI card on the Dashboard. Click the card to filter Object Browser to ManagementPlane objects.

### UserAccess

[Define: Standard identities with limited, scoped permissions — typical end-users, service accounts with narrow access. Lowest privilege tier.]

**In the GUI:** UserAccess identities appear in the UserAccess KPI card on the Dashboard. Click the card to filter Object Browser to UserAccess objects.

## Applied vs Computed Tiers

[Explain: When EntraOps classifies an identity, it produces a *computed tier* — derived automatically from role assignments and classification templates. If an administrator overrides this via the Object Reclassification screen or an exclusion rule, the resulting tier becomes the *applied tier*.]

**Visual distinction in the GUI:** A **dashed badge** indicates a computed tier (system-derived). A **solid badge** indicates an applied tier (explicitly set or overridden). When browsing the Object Browser, the badge style tells you at a glance whether EntraOps or an admin determined the tier.

## Glossary

| Term | Definition | Where in GUI |
|------|------------|--------------|
| ControlPlane | Identities with unrestricted or near-unrestricted tenant access | Dashboard KPI card, Object Browser filter |
| ManagementPlane | Identities with significant operational access below global admin | Dashboard KPI card, Object Browser filter |
| UserAccess | Identities with standard scoped permissions | Dashboard KPI card, Object Browser filter |
| applied tier | The effective tier for an identity — either system-computed or explicitly set/overridden by an admin | Object Browser badge (solid), Object Reclassification screen |
| computed tier | The tier derived automatically from role assignments and classification templates | Object Browser badge (dashed), Object Reclassification screen |
| exclusion | A rule in Global.json that prevents an identity from being classified into a specific tier | Exclusions screen |
| override | An admin-set tier assignment for a specific identity that takes precedence over the computed tier | Object Reclassification screen |
```
